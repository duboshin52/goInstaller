# goInstaller

Единый установщик продуктов серии go: **goVLESS pro**, **goTelegram pro**,
**goDNS pro**, **goKaskad pro**, **goWARP pro**, **goAmnezia pro**.

Сам он ничего не настраивает. Его работа — до запуска штатного установщика
продукта проверить машину: ОС, кто держит нужные порты, какие соседи уже
стоят и чем это грозит, — и только потом передать управление установщику
продукта. Каждый продукт по-прежнему ставится своим кодом.

## Установка и запуск

Публичная сборка работает без GitHub token:

```bash
bash <(curl -fsSL \
  https://raw.githubusercontent.com/duboshin52/goInstaller/main/go-installer.sh)
```

Для запуска от root используйте `sudo bash` либо войдите в SSH под `root`.
Необязательный `GH_TOKEN` можно задать только для увеличения лимита GitHub API.
Прежний режим закрытых репозиториев включается через `GOINST_PUBLIC=0`.

После первого запуска появляется команда **`goinstall`**. Прежнее имя
`go-installer` остаётся ссылкой на неё. Запущенный так из другой ветки
(`…/goInstaller/test-shield/go-installer.sh`) скрипт ставит в `goinstall` свою
же версию: ищет ветку ровно с ней (main, dev, остальные — не больше 30; к API
GitHub — запрос списка веток, без списка — ещё до трёх) и запоминает её для
обновлений. Не нашлась (или эта версия в нескольких ветках с разным
содержимым), а `goinstall` уже стоит — его не заменяет и говорит почему и как
быть: `goinstall --self-update <ветка>` или запуск из файла.

```
goinstall                      меню
goinstall --list               что установлено
goinstall --ports              кто какие порты держит
goinstall --versions           версии на сервере и в ветках GitHub
goinstall --key [set|check|forget] ключ доступа: ввести, проверить, удалить
goinstall --net                проверить размер пакета до GitHub
goinstall --components [refresh]   системные пакеты продуктов: что стоит и что доступно
goinstall --components update <id…|all> [--yes]   обновить их пакеты apt
goinstall --os-upgrade [--yes]   обновить Ubuntu 20.04/22.04 до 24.04 (сначала бэкап)
goinstall --os-upgrade status    ход и итог обновления Ubuntu
goinstall --os-upgrade dismiss   снять отметку «прервано» (журнал остаётся)
goinstall --shield [status|check|update|on|off|vk on|vk off|remove] [--yes]   защита от сканеров
goinstall --shield stats [24h|7d|30d|all|top [период]|size|reset [--yes]]   её статистика
goinstall --uninstall          удалить сам goInstaller; продукты не трогает
goinstall --summary on|off     сводка при входе по SSH: включить или выключить
goinstall --check <id> [режим]    проверка без установки; код 0 — ок,
                                  1 — препятствия, 2 — замечания
goinstall --install <id> [режим] [ветка]   сразу к установке; код —
                                  установщика, 1 — продукт не встал
                                  или остался бесплатный
```

`id`: `govless` `gotelegram` `godns` `gokaskad` `gowarp` `goamnezia`.
Режим: `pro` или `lite`; у goAmnezia pro — `lazy`, `pro`, `lite_site`, `lite`
(Ленивый pro, pro, Semi-pro, Lite — как в его мастере). Чужое слово — отказ
с кодом 64 и перечнем режимов, а не проверка пустого набора портов.

Из локального дерева, без GitHub: `GOINST_SRC_<id>=/путь` (для goDNS pro это
превращается в `GODNS_LOCAL_SRC`, для goAmnezia pro — в `GOAMNEZIA_LOCAL_TREE`:
запускается `bootstrap.sh` дерева, тем же путём, что настоящая установка). Ветка: `GOINST_REF_<id>`. Ключ goWARP pro:
`GOWARP_KEY`. Ленивый pro у goAmnezia pro: домен — `GOINST_LAZY_DOMAIN`
(без неё продукт спросит сам), число ключей — `GOINST_LAZY_KEYS`. Язык спрашивается первым экраном, см. раздел «Язык»;
`GOINST_LANG=ru|en` задаёт его без вопроса. Прежнее нумерованное меню вместо «Аркады»: `GOINST_PLAIN_MENU=1`.
Цвет: `GOINST_COLOR=true|256|16|none` (иначе по терминалу, `NO_COLOR` уважается),
фон: `GOINST_BG=light|dark`, ASCII-рамки: `GOINST_ASCII=1`.
Не спрашивать GitHub о версиях: `GOINST_NO_NET=1`. Срок годности ответа:
`GOINST_VER_TTL` в секундах, по умолчанию минута. Автообновление главного
меню: `GOINST_MENU_REFRESH` в секундах, по умолчанию 180, `0` выключает. Ветки одного продукта:
`GOINST_REFS_<id>`, например `GOINST_REFS_govless="main dev rc1"`.

решения к нему). Пока оно открыто, терминал переключён на отдельный экран;
после выхода всё возвращается как было, даже если меню упало.

При запуске заставка показывает опрос GitHub построчно: goInstaller, ключ,
шесть продуктов, у каждой строки свой итог. Если сведения моложе минуты,
заставки нет, сразу меню. Открытое меню само спрашивает GitHub раз в три
минуты (`GOINST_MENU_REFRESH`), при исчерпанном лимите — не спрашивает.

Слева продукты и служебные пункты, справа карточка выбранного: версии на
сервере и в ветках, порты, службы, режим. Под окнами замечания: сертификат
скоро истекает, служба продукта не работает. Против каждого продукта одно
слово: версия установленного, `↑ 2.10.49` (обновление в его ветке),
`✚ новое` (новый продукт серии), `◆ бесплатный`, `○ готов`, `! замечания`,
`◆ только Lite`, `✗ нельзя`.

Управление одно на всех экранах:

- цифра — пункт сразу; стрелки и Enter — то же курсором (на телефоне удобнее цифры);
- `p` — карта портов, `r` — ключ, `l` — язык, `u` — обновить goInstaller,
  `c` — компоненты, `s` — защита от сканеров, `o` — обновление Ubuntu (на 20.04 и 22.04);
  все три — с любого экрана, как `p`;
- Esc или `0` — назад, `q` — выход;
- русская раскладка понимается: `з к д г й с ы ф щ` — это `p r l u q c s a o`;
- привычка прежнего меню «цифра, Enter» работает: Enter сразу за цифрой
  ничего не нажимает на следующем экране — иначе на подтверждении он
  запускал бы установку вслепую; та же клавиша, нажатая несколько раз
  подряд, — одно нажатие;
- вставка из буфера пунктов не нажимает: пачка разных символов, пришедшая
  за миллисекунды, пропускается, и внизу экрана об этом сказано.

Раскладка зависит от ширины окна и пересчитывается на ходу: от 80 колонок —
два окна рядом, от 46 до 79 — один столбец, меньше 46 × 24 — просьба
растянуть окно и `goinstall --list` как выход.

Цвет — по терминалу: 24 бита, 256 цветов, 16 или без цвета (`NO_COLOR`,
`TERM=dumb`), для тёмного и светлого фона свои. Если в сессии нет UTF-8
(SSH принёс локаль, которой на сервере нет), меню переходит на C.UTF-8, а
если нет и её — на ASCII-рамки: иначе bash считает байты, и рамки рвутся.

Установка идёт мастером: режим (если у продукта их несколько) → проверка
портов → ветка → подтверждение → установщик продукта в обычном терминале →
сверка итога, то есть с какой ветки и какой версии продукт встал на деле.

Прежний нумерованный список остался. Он включается сам, когда полноэкранное
меню невозможно (нет терминала на входе или выходе, `TERM=dumb`), и по
`GOINST_PLAIN_MENU=1`.

Готовность против продукта считает та же `preflight`, что и `--check`, а не
отдельная проверка рядом: разойдясь, они обещали бы «готов» там, где
установка потом отказывает. Значения: `готов`, `готов, есть замечания`,
`не на 443` (у goDNS pro: 443 занят соседом, DoH встанет рядом, на 4443, —
в карточке это сказано словами), `только Lite` (порты требовательного
режима заняты, а скромный проходит),
`443 занят: goDNS pro`, `система не подходит`, `конфликт с соседом`.
Против goVLESS pro, goKaskad pro и goTelegram pro вместо версии может стоять
`бесплатный Lite 1.3.6`, `бесплатный Kaskad` или `бесплатный MTProxy`, см.
разделы о бесплатных версиях ниже.

## Сводка при входе

Вошли по SSH — и сразу видно, что вышли обновления, появился новый продукт
серии или скоро истекает сертификат:

```
╔═ goInstaller · vpn-fin-1 ═══════════════════════════════ сведения от 14:05 ═╗
║  ↑ goTelegram pro   2.10.46 → 2.10.49   обновление в main                   ║░
║  ✚ goAmnezia pro    1.0.2               новый продукт серии, main           ║░
║                                                                             ║░
║  ! vpn.example.com  сертификат истекает через 9 дней → certbot certificates ║░
║  диск 58 % · память 41 % · нагрузка 0.4                                     ║░
╚═ goinstall — открыть меню ══════════════════════════════════════════════════╝░
```

Это единственное, что goInstaller оставляет работать на сервере, поэтому
ставится только с согласия: вопрос задаётся один раз, при первом запуске
меню. Потом — `goinstall --summary on` и `goinstall --summary off`.

Что ставится и зачем:

- таймер `goinstall-watch.timer` — раз в 30 минут, со случайным сдвигом до
  10 минут, запускает `goinstall --watch`: тот берёт сводку версий клуба
  (см. ниже) и записывает сведения в `/opt/go-installer/summary`;
- `/etc/profile.d/goinstall-summary.sh` — при входе печатает сводку из этого
  файла (`goinstall --motd`). Сеть при входе не трогается никогда. Только
  для root, только в терминале, `~/.hushlogin` уважается.

Когда в сводке есть новое или замечания, под ней идёт отсчёт на 5 секунд:
Enter — открыть goinstall, любая другая клавиша или тишина — в консоль. Когда
всё актуально, отсчёта нет: ждать нечего. Если к началу отсчёта что-то уже
набрано, его тоже нет: набранное уходит в консоль целиком.

`--summary off` снимает всё: таймер, службу, скрипт входа и файл сведений.

Сертификаты проверяются по карте продуктов: домен берётся из `config.json`
стоящего продукта, подсказка — проверка, которая подходит именно ему.

| Продукт | Сертификат | Тревога | Подсказка |
|---|---|---|---|
| goVLESS pro | Let's Encrypt домена | меньше 14 дней | `certbot certificates` |
| goVLESS pro, панель Lite | IP-сертификат acme.sh (`/root/cert/ip`), живёт ~6 дней | меньше 2 дней | `acme.sh --list` |
| goTelegram pro, режим pro | Let's Encrypt домена | меньше 14 дней | меню `gotelegram`: Сайт / SSL |
| goAmnezia pro, `"cert": "letsencrypt"` | Let's Encrypt домена | меньше 14 дней | меню `goamnezia`: Сертификат |
| goDNS pro, свой (`cert_owned_by_godns`) | Let's Encrypt домена | меньше 14 дней | меню `godns`: Сертификат |

goDNS pro на сертификате соседа отдельной строки не даёт: домен тот же.
Команд, которые трогают чужой сертификат (`renew`, `--force-renewal`,
`revoke`, `--install-cert`), в подсказках нет и не будет.

Службы продукта проверяются только те, что стоят на машине. goWARP pro
ставит `warp-svc` только для 3X-UI, а `warp-bot` только с ботом. До 1.0.8
сводка называла отсутствующие службы упавшими: «warp-svc не работает».
Тревога — только у включённой службы, которая не работает. Выключенная
человеком (`systemctl disable`) видна в карточке кружком ○ без тревоги.

## Язык

При первом запуске меню или установки первым экраном идёт выбор языка,
цифрой: `1` — русский, `2` — английский. Только после него начинаются
проверки системы, прав, ключа и версий, так что и отказы, и подсказки
человек читает на своём языке. Enter берёт язык, уже выбранный в соседнем
продукте на этой машине, а если такого нет — русский.

Выбор запоминается в `/opt/go-installer/.language`, дальше установщик не
спрашивает. Сменить — пункт «Язык» в главном меню. Задать без вопроса —
`GOINST_LANG=ru` или `GOINST_LANG=en`.

Справочные команды — `--list`, `--ports`, `--versions`, `--check`, `--key` —
язык не спрашивают, чтобы не ломать запуск из скриптов: они берут
запомненный, иначе язык соседнего продукта, иначе локаль сессии.

Язык в продукты не передаётся. У goVLESS pro, goTelegram pro, goDNS pro и
goAmnezia pro свой экран выбора, goKaskad pro и goWARP pro только на русском.

## Ключ доступа

В публичной сборке ключ не требуется: установка, опрос версий и самообновление
работают анонимно. Сохранённый ключ закрытой сборки не подхватывается, чтобы
отозванный ключ не вызывал ошибку 401 на публичных запросах. Явно заданный в
окружении `GH_TOKEN` используется только для увеличения лимита GitHub API.

Для прежнего режима закрытых репозиториев задайте `GOINST_PUBLIC=0`. Тогда ключ
берётся из `GH_TOKEN` или `/opt/go-installer/token` и проверяется запросами ко
всем продуктовым репозиториям. Возможных исходов четыре.

| Ответ GitHub | Что это значит | Что делает установщик |
|---|---|---|
| все 200 | ключ читает всё | продолжает молча |
| часть 403/404 | ключ рабочий, но неполный | называет продукты, которые не скачаются, и даёт ссылку |
| 401, либо ни одного 200 | ключ отозван или чужой | удаляет сохранённый и просит новый |
| сети нет | ключ ни при чём | оставляет как есть и говорит об этом |
| 403 с `x-ratelimit-remaining: 0` или `retry-after` | исчерпан общий лимит GitHub | оставляет ключ и называет время, когда лимит восстановится |

Отдельные команды для необязательного ключа: `goinstall --key set`,
`--key check`, `--key forget`.

**Лимит GitHub.** Анонимные API-запросы ограничены по IP; с явно заданным
`GH_TOKEN` действует отдельный лимит аккаунта. При исчерпании лимита на экране
остаются прежние сведения и время сброса. Экономят лимит три приёма:

- **Условные запросы.** Прошлый ответ помечен ETag. Если на GitHub ничего не изменилось, он отвечает 304, и такой ответ в лимит не засчитывается. Проверено на ключе клуба: первый опрос стоит 19 запросов, повторный — ни одного.
- **Только хеш коммита.** GitHub отдаёт 40 байт вместо 59 КБ.
- **Кеш версии по коммиту.** Для уже виденного коммита версия берётся из кеша, файл из ветки не качается.
- **Сводка версий на весь клуб.** Фоновый опрос не ходит по репозиториям сам, см. ниже.

### Сводка версий для клуба (GitHub Actions)

Таймер сводки стоит на сотнях серверов клуба, и каждый опрашивал бы шесть
репозиториев сам — два десятка запросов в полчаса с сервера на одном ключе.
Условные запросы основной лимит не тратят, но у GitHub есть и вторичный, на
частоту, и его они не снимают. Поэтому версии для всех собирает GitHub
Actions (`.github/workflows/versions.yml`):

- раз в час, в :23, запускается `go-installer.sh --digest` — тот же код
  опроса, что и на сервере, — и кладёт `versions.txt` в ветку `versions`
  этого репозитория (один коммит без истории). Публикует, когда сводка
  изменилась, а без изменений — если прошлой больше двух часов: расписание
  GitHub на деле срабатывает раз в 3–9 часов, и сводка не должна дожить до
  12 часов, после которых ей не верят;
- таймер на сервере берёт этот файл одним условным запросом: пока сводка та
  же, GitHub отвечает 304, и это ноль запросов из лимита (проверено на
  эндпоинте `contents`: `X-Ratelimit-Used` на 304 не растёт);
- сводке старше 12 часов сервер не верит. Нет её или она старая — сервер
  спрашивает сам, но только про стоящие продукты и себя, без проверки ключа;
- открытое меню спрашивает GitHub напрямую: там важна точность, а людей с
  открытым меню единицы.

Формат — строки, чтобы читать без jq:

```
format=1
generated=1790000000
godns @refs main dev
godns main 1.0.1 <хеш коммита>
godns dev 1.0.2 <хеш коммита>
@self main 1.0.1 <хеш коммита>
```

Сервер проверяет каждое поле по строгому образцу и принимает сводку только
целиком: неполная, чужого формата или с посторонними символами в кеш не
попадает. Сборка без веток хоть у одного продукта падает, и Actions не
публикует ничего — остаётся прошлая сводка.

Для работы нужен секрет репозитория `GOINST_READ_TOKEN`: ключ, который
читает все шесть репозиториев продуктов и этот. Лучше отдельный
fine-grained токен только на чтение (Contents и Metadata: Read-only), а не
ключ клуба: тогда замена ключа клуба сводку не ломает. Каждый запуск длится
около 7 секунд, но GitHub считает минуту: раз в час — около 720 минут в месяц
из бесплатных 2000.

Ключ нигде не попадает в аргументы команд: и при проверке, и при
скачивании он уходит заголовком из временного конфига `curl` с режимом
0600. Дочернему установщику он передаётся переменной окружения, которую
тот читает сам.

## Версии

Третья колонка показывает, что лежит в ветках репозитория, и отмечает
стрелкой то, что новее установленного. Номер версии читается из одного и
того же места локально и на GitHub: таблица одна на оба случая.

| Продукт | Файл | Переменная | Ветки |
|---|---|---|---|
| goVLESS pro | `lib/common.sh` | `GOVLESS_VERSION` | main, dev |
| goTelegram pro | `lib/common.sh` | `GOTELEGRAM_VERSION` | main, dev |
| goDNS pro | `lib/common.sh` | `GODNS_VERSION` | main, dev |
| goKaskad pro | `install.sh` | `KASKAD_VERSION` | main, dev |
| goWARP pro | `warp.sh` | `WARP_VERSION` | main |
| goAmnezia pro | `lib/common.sh` | `GOAMNEZIA_VERSION` | main, dev |

Список веток снят с GitHub, а не с документации. У goWARP pro ветки `dev` нет.

Ветки узнаются у GitHub при запуске, а не берутся из списка в коде: у
goDNS pro `main` появилась уже после того, как список был написан, а у
goWARP pro ветки `dev` нет вовсе. Предлагаются только `main` и `dev` —
рабочие ветки авторов (`rc1`, `alfa-v2`, `backup/*`) в выбор не попадают.
Своя ветка задаётся через `GOINST_REFS_<id>`.

goKaskad pro 3 лежит в `dev`, на `main` — 2.x. Ветку обновлений 3.x пишет в
`/etc/kaskad/config` (`KASKAD_BRANCH`), goInstaller передаёт её установщику и по
ней узнаёт, с какой ветки продукт стоит: Enter в выборе ветки оставляет 3.x на
`dev` и не откатывает на 2.x. Ветку можно задать сразу:
`goinstall --install gokaskad dev`. Язык, выбранный в goInstaller, уходит
установщику в `KASKAD_LANG` при первой установке: 3.x не спрашивает его второй
раз, а выбранный потом в меню продукта обновление не переписывает.

Сам goInstaller обновляется так же: его версия читается из его же ветки, и
пункт «Обновить goInstaller» появляется, только когда там действительно
новее. Ветка — самая новая из main, dev и той, из которой goInstaller ставился
(например, тестовой); экран подтверждения её называет. Когда main догоняет
тестовую ветку, goInstaller возвращается к main. Отдельно —
`goinstall --self-update [ветка]`.

### Как узнаётся номер версии

Одинаково в обоих случаях: скачивается или читается **один файл**, из него
берётся присваивание переменной в начале строки. Ни клона, ни тега, ни
релиза — номер берётся оттуда же, откуда его берёт сам продукт.

- **Локально** — из дерева установленного продукта: `/opt/govless-installer`,
  `/opt/gotelegram`, `/opt/godns-installer`, `/opt/goamnezia`, а у goKaskad pro и
  goWARP pro из их единственного файла в `/usr/local/bin`. Если каталог снесли,
  у goDNS pro номер ещё лежит в его `config.json`.
- **На GitHub** — `raw.githubusercontent.com/<репозиторий>/<ветка>/<файл>`,
  то есть голова ветки на момент запроса. Один файл на ветку, ничего больше.

Путь к файлу — подсказка, а не жёсткое правило: если в нём версии нет,
проверяются `lib/common.sh`, `install.sh`, `bootstrap.sh` и одноимённый
скрипт, и годится любая переменная вида `…VERSION=`. Присваивание ищется
только в начале строки, поэтому упоминание в комментарии или в `echo`
версией не считается. Версии сравниваются через
`sort -V`, иначе 0.9.0 оказалось бы новее 0.10.0.

Отсюда важное ограничение: показывается то, что **объявлено в коде ветки**.
Продукт, забывший поднять свою переменную, покажется старым. В goDNS pro для
этого есть отдельное правило поднимать версию при каждом пуше.

Опрос идёт при запуске и дальше сам раз в три минуты, пока открыто главное
меню: все запросы разом, с тайм-аутом на каждый. Экран перерисовывается на
месте, курсор остаётся где был, а внизу видно время последних сведений.
Ответ живёт в `/opt/go-installer/versions` одну минуту: этого хватает, чтобы
возврат из подменю не трогал сеть, и мало, чтобы свежий пуш прятался.
После минуты старый ответ по-прежнему показывается, пока не придёт новый. Пункт «Обновить сведения о версиях» спрашивает заново. В публичной
сборке опрос работает без ключа. Если необязательный `GH_TOKEN` задан явно,
он уходит заголовком из файла с режимом 0600, а не в аргументах команды.

Стороннего движка меню (`whiptail`, `dialog`) здесь нет намеренно: его
рамка выглядит чужой рядом с меню самих продуктов, он не умеет цветной
колонки состояния и возвращает выбор в stderr, куда проект пишет журнал.
Отрисовка повторяет проверенный список с галочками из goDNS pro: строки
готовятся заранее, экран перерисовывается целиком от `\033[H`, ширина
колонок считается в символах, а не байтах.

## Выбор ветки

Перед запуском установщика спрашивается, с какой ветки ставить. В вопросе
стоят номера версий, поэтому выбор делается по тому, что там лежит, а не по
названию ветки.

```
  С какой ветки ставить?
  1) main   стабильная          2.10.46  та же, что стоит
  2) dev    экспериментальная   2.11.0   новее установленной 2.10.46
  Enter — оставить ту, с которой стоит: main
```

Режим у установленного продукта **не спрашивается**: он записан самим
продуктом в его `config.json` под ключом `mode`, оттуда и читается. Так
делают все три продукта с режимами. Спросить принудительно —
`GOINST_ASK_MODE=1`.

Все вопросы отвечаются цифрами, включая подтверждение запуска: `1` — да,
`2` — нет, Enter — умолчание. Буквенного `[Y/n]` нет нигде: на русской
раскладке он требует переключения ради одного символа.

Умолчание при обновлении — ветка, с которой продукт стоит: goTelegram pro и
goAmnezia pro записывают её в `.install-source`. Переезд со стабильной ветки на
экспериментальную не должен случаться от промаха по Enter. Если ветка у
продукта одна, как у goKaskad pro и goWARP pro, вместо вопроса печатается
строка о том, какая именно.

Ветку можно задать сразу: `goinstall --install govless pro dev`.

**Смена ветки у уже установленного goVLESS pro.** До 1.3.7 его загрузчик
печатал «✓ Updated to latest dev», оставаясь на прежней ветке. С 1.3.7
загрузчик goVLESS pro переключает ветку честно и сам лечит клоны, поставленные
раньше. goInstaller его клон не трогает.

После любого установщика goInstaller сам сверяет итог: с той ли ветки
стоит продукт и та ли у него версия, что лежит в выбранной ветке. Надпись
«обновлено» на экране продукта доказательством не считается.

## goVLESS pro поверх бесплатного Lite

Бесплатный Lite из инструкции (репозиторий `anten-ka/govless-lite-version`)
ставится туда же, куда goVLESS pro: код клоном в `/opt/govless-installer`,
настройки в `/opt/govless/config.json`, команда `govless`. По этим
признакам его не отличить от pro, и до 0.9.2 goInstaller показывал его как
установленный goVLESS pro. Пункт «Открыть меню продукта» запускал меню Lite,
а обновление приводило туда же: загрузчик pro «обновлял» клон Lite из
репозитория Lite.

Теперь Lite узнаётся по тому, откуда взят код: origin клона ведёт в
репозиторий с именем `govless-lite-version`. Тогда:

- в главном меню против goVLESS pro стоит жёлтое `бесплатный Lite 1.3.6`;
- в подменю первый пункт — «Поставить goVLESS pro поверх Lite», пункта
  «Открыть меню продукта» нет, команду Lite goInstaller не запускает;
- перед вопросами goInstaller говорит, что будет: панель 3X-UI, ключи и
  пользователи останутся, заменится только код в `/opt/govless-installer`;
- ветка клона Lite умолчанием не служит, у Lite своя `dev`;
- `--list` и `--versions` пишут `Lite` рядом с номером.

Сам клон заменяет загрузчик goVLESS pro, а не goInstaller. Новый клон он
кладёт рядом и подменяет старый только целиком, поэтому без ключа или сети
сервер остаётся с Lite и рабочей командой `govless`. Затем `govless.sh` из
pro открывает своё меню в прежнем режиме Lite: схема настроек у Lite и pro
одна. Режим Pro со своим доменом и TLS включается там же, в разделе VPN
пунктом смены режима, ключи клиентов при этом сохраняются.

Если после установки в `/opt/govless-installer` остался клон Lite, проверка
итога так и говорит: pro не встал, что бы ни напечатал загрузчик.

## goKaskad pro поверх бесплатного Kaskad

Бесплатный Kaskad из инструкции (`anten-ka/kaskad`) копирует себя в ту же
`/usr/local/bin/gokaskad`, что и goKaskad pro. До 0.9.3 goInstaller писал
«goKaskad pro установлен», а «Открыть меню продукта» открывал бесплатное меню.
Отличает их строка версии: `KASKAD_VERSION=` есть в каждой версии pro и ни в
одной бесплатной.

Тогда в меню стоит `бесплатный Kaskad`, первый пункт — «Поставить goKaskad pro
поверх Kaskad», бесплатную команду goInstaller не запускает. goKaskad pro с
2.12 при запуске забирает правила бесплатной версии себе: они продолжают
работать и видны в его меню. Правила бесплатного Kaskad идут без меток
`kaskad:`, и раньше pro их не видел, а своё правило на том же порту ставил за
старым DNAT, где оно не срабатывало.

## goTelegram pro поверх бесплатного MTProxy

Бесплатный MTProxy из инструкции (`anten-ka/gotelegram_mtproxy`) держит прокси
в Docker-контейнере `mtproto-proxy` (mtg), по умолчанию на 443, и ставит свою
команду `gotelegram`. goInstaller звал этот контейнер чужим и запрещал режим
pro, хотя установщик goTelegram pro сам находит его, спрашивает и
останавливает. Теперь контейнер назван «MTProxy (mtg)», для goTelegram pro он —
замечание, а не препятствие. В замечании сказано главное: секрет mtg в telemt
не переносится, клиентам понадобится новая ссылка, и старый прокси
остановится сразу после ответа «да», ещё до выбора режима.

Бесплатный скрипт, запущенный уже поверх pro, копирует себя в
`/usr/local/bin/gotelegram`. До goTelegram pro 2.10.50 команда была симлинком,
и копия затирала сам установщик pro; с 2.10.50 это обёртка, и затирается только
она. В обоих случаях goInstaller теперь видит бесплатный код, пишет
`бесплатный MTProxy`, и первый пункт ставит pro заново, а не запускает
бесплатный скрипт.

## Компоненты

Пункт «c Компоненты» в меню и команда `goinstall --components` показывают
системные компоненты, которые нужны продуктам: что стоит, что доступно в
apt, для каких продуктов, что будет при обновлении.

```
goinstall --components                  таблица
goinstall --components refresh          сначала apt-get update, потом таблица
goinstall --components update nginx     обновить nginx (спросит 1 Да / 2 Нет)
goinstall --components update all --yes обновить всё без вопроса
```

Код `update`: 0 — обновлено, 1 — ошибка apt, 2 — обновлять нечего (или
отказ на вопросе), 3 — нет терминала и нет `--yes` (отказ сразу, до
вопросов; тот же код у `--uninstall`), 64 — неизвестный компонент.

| Компонент | Пакеты | Для |
|---|---|---|
| `nginx` | nginx и его модули | goVLESS pro, goTelegram pro, goAmnezia pro, goKaskad pro |
| `certbot` | certbot, python3-certbot, python3-acme | goVLESS pro, goTelegram pro, goDNS pro, goAmnezia pro, goKaskad pro |
| `docker` | docker.io (или docker-ce), containerd, runc | goAmnezia pro, goWARP pro |
| `python3` | python3.X, на который указывает /usr/bin/python3, и его venv | goVLESS pro, goTelegram pro, goDNS pro, goKaskad pro, goAmnezia pro |
| `dnsdist` | dnsdist (репозиторий PowerDNS, линия 2.0) | goDNS pro |
| `warp` | cloudflare-warp | goWARP pro |
| `cloudflared` | cloudflared | goVLESS pro |
| `firewall` | iptables, iptables-persistent, netfilter-persistent | goKaskad pro, goTelegram pro, goAmnezia pro |
| `nftables`, `wireguard`, `strongswan`, `ocserv`, `openvpn` | одноимённые | goKaskad pro (WireGuard — и goTelegram pro) |
| `tools` | curl, git, jq, openssl, sqlite3, qrencode, socat, ca-certificates | все |

Строка видна, только если главный пакет стоит. Вместе с пакетами группы
обновляются стоящие пакеты того же исходного пакета (nginx — с nginx-common
и модулями одной версии); остальные зависимости apt дотягивает сам.
Закреплённый пакет (`apt-mark hold`) не обновляется и в «Обновить всё» не
входит. Закреплён главный пакет группы (nginx) — не обновляется вся группа:
родня без него разъехалась бы с ним версиями; строка — `!`, а не `↑`.
Новее ли кандидат — только по `dpkg --compare-versions` (эпоха, `~`,
ревизия): кандидат ниже стоящего (пин) обновлением не считается.

**goInstaller обновляет только пакеты apt** и только по выбору человека с
подтверждением цифрой, одной командой:

```
DEBIAN_FRONTEND=noninteractive NEEDRESTART_MODE=a apt-get -y -o DPkg::Lock::Timeout=300 \
  -o Dpkg::Options::=--force-confdef -o Dpkg::Options::=--force-confold \
  install --only-upgrade --no-remove <пакеты>
```

Никаких `apt-get upgrade`, `dist-upgrade`, `autoremove` и установки нового.
`--no-remove` — иначе iptables-persistent удалил бы ufw; confold — иначе
пропали бы правки nginx.conf goTelegram pro. Перед вопросом идёт пробный
прогон `apt-get -s` с теми же ключами: сколько пакетов обновится и что apt
отложил (kept back, поэтапный выпуск Ubuntu). Вывод apt виден целиком и
пишется в `/opt/go-installer/logs/components-<дата>.log` (каталог 0700).
После — итог по строкам («стала», «осталась — apt отложил», «apt вышел с
кодом»), какие службы перезапустил needrestart и какие службы стоящих
продуктов не работают. `NEEDRESTART_MODE=a` — решение заказчика 14.10:
службы на обновлённых библиотеках (openssl, libcurl, python) перезапустятся
сами, VPN-клиенты переподключатся; об этом сказано на подтверждении.

Свежесть списков apt («списки apt от …») — время последней удачной
проверки: самое позднее из `/var/lib/apt/periodic/update-success-stamp`,
своей отметки удачного `apt-get update` (`/opt/go-installer/.apt-ok`) и
`/var/cache/apt/pkgcache.bin`. mtime `*Release` — время публикации на
зеркале, по нему подпись не менялась и после `r`; берётся, только если
ничего из этого нет. Журнал apt — `/opt/go-installer/logs/components-<дата>.log`
(каталог 0700, файл 0600). Старше 12 часов (`GOINST_APT_MAXAGE`, секунды) — экран сам запускает
`apt-get update` в фоне, если прошлая попытка, удачная или нет, была больше
часа назад (`GOINST_APT_RETRY`; отметка — `/opt/go-installer/.apt-check`);
вручную — `r`. Ограничение — 180 секунд, замок apt ждётся до 60. Не вышло —
заметка с причиной, показ по прежним спискам. `u` и `a` проверку не ждут:
прерывают её и обновляют по прежним спискам, о чём и говорят. Проверка
живёт, только пока открыт экран: уход с него, установщик продукта,
самообновление, выход и Ctrl-C её гасят вместе с apt-get.

В «Аркаде» экран «Компоненты»: слева строки apt с отметками `[✓]`, под
чертой — движки продуктов, ниже действия; справа — карточка строки под
курсором. Пробел или Enter — отметить, цифра `1`–`9` — отметить эту строку,
`u` — обновить отмеченные (без отметок — строку под курсором), `a` — всё,
`r` — проверить обновления, `0` или Esc — назад. Длинный список
показывается срезом вокруг курсора. В нумерованном меню у движков строкой
ниже — для кого и кто обновляет, у сломанного окружения бота — что сломано
и как починить.

**Движки продуктов только показываются** — версия и кто их обновляет:
3X-UI и его Xray, telemt, образы и модуль ядра AmneziaWG, xray прокси API
Telegram, accel-ppp, acme.sh, окружения ботов. Обновление в обход продукта
ломает совместимость: telemt вернётся к версии из настроек продукта, образы
AmneziaWG закреплены по digest, goVLESS pro проверен с той версией 3X-UI,
что стоит.

Окружение бота (`/opt/govless/venv`, `/opt/gotelegram-bot/venv`,
`/opt/godns/bot/venv`, `/opt/goamnezia-bot/venv`) после смены python
ломается и само не чинится. Если его python не запускается или запускается
не тот, на котором окружение собрано (`pyvenv.cfg`), это замечание `✗` под
меню и в сводке при входе, а в карточке — как починить. С системным python3
не сравнивается: goVLESS pro собирает окружение на первом из python3.13…3.9,
и после смены Ubuntu бот на оставшемся python3.10 работает. Как починить: удалить только каталог venv и поставить бота из меню продукта
(у goDNS pro — мастером бота, не через «снять бота»: так пропадёт токен).

## Обновление Ubuntu до 24.04

На Ubuntu 20.04 и 22.04 в главном меню есть пункт «o» (на русской раскладке
— «щ»): обновить систему до Ubuntu 24.04 LTS одной кнопкой. С 20.04 это два
прыжка, 20.04 → 22.04 → 24.04; после перезагрузок обновление продолжается
само. Debian, 18.04, не-LTS и 24.04 и новее — пункта нет: на 24.04 штатная
программа уже предлагает 26.04, туда goInstaller не идёт.

**Сначала бэкап.** Сделайте снимок сервера в панели хостера: если
обновление прервётся, вернуть сервер можно только из снимка. Обновление идёт
20–60 минут (с 22.04 — 15–40), перезагрузок 2–4. SSH будет отключаться, на
последнем прыжке — до 10 минут; это нормально, обновление идёт само. В
контейнере (OpenVZ, LXC) ядро задаёт хостер: обновить выпуск отсюда нельзя,
только переустановить сервер на 24.04 в панели хостера.

```
goinstall --os-upgrade          проверка, предупреждение, вопрос 1 Да / 2 Нет, запуск;
                                код: 0 — запущено, 1 — отказ, 2 — ответ «нет»,
                                3 — уже идёт, 4 — без терминала и без --yes
goinstall --os-upgrade --yes    то же без вопроса
goinstall --os-upgrade status   ход и итог; код: 0 — нет или готово, 1 — прервано, 3 — идёт
goinstall --os-upgrade dismiss  снять отметку «прервано» — обновлять не буду
```

Без терминала и без `--yes` команда отказывает сразу, до вопросов, с кодом 4.
У `--uninstall` и `--components update` такой отказ — код 3, но здесь 3
означает «идёт», как у `status`, и смешивать их нельзя. В меню
курсор стоит на «Назад»: Enter обновление не запускает, только «1 Бэкап
сделан — обновить до 24.04».

Перед запуском goInstaller проверяет сервер. Запуск запрещён: контейнер; на
`/` меньше 5 ГБ (пик расхода — около 4 ГБ); отдельный `/boot` с меньше чем
300 МБ; `dpkg --audit` не пуст; замок apt держит другой процесс (обычно
автообновления — подождать); нет связи с `changelogs.ubuntu.com` (без неё
штатная программа не найдёт выпуск). Замечания: 5–8 ГБ свободно, памяти
меньше 1 ГБ, `Prompt` в release-upgrades не `lts`. И что будет с тем, что
стоит, — отдельной строкой, что goInstaller сделает сам:
- вернёт на 24.04 источники apt продуктов (dnsdist goDNS pro,
  cloudflare-warp goWARP pro, cloudflared goVLESS pro);
- сохранит модули nginx (иначе на 24.04 nginx не запустится: апгрейдер
  сносит авто-пакеты `nginx-core`, `libnginx-mod-stream` как ненужные);
- сохранит правила файрвола, если ufw включён вместе с iptables-persistent:
  на 24.04 ufw удаляется (они несовместимы), и перед этим идёт
  `netfilter-persistent save`. Управлять правилами через ufw потом нельзя.

Ещё сведения: окружения ботов после обновления не запустятся, пока не
переустановить бота в меню продукта (путь — как на экране «Компоненты»);
goKaskad pro после обновления надо запустить (3.x предложит nftables, 2.x —
проверить проброс); модули DKMS пересоберутся; контейнеры Docker с
автоперезапуском поднимутся сами.

Ход виден в меню («Ubuntu: обновление, шаг N из M») — экран обновляется раз в
2 секунды — и при входе по SSH: в сводке, если она включена, иначе одной-двумя
строками временного `/etc/profile.d/goinstall-osupgrade.sh` (только root,
только терминал, `~/.hushlogin` уважается; уходит сам после просмотра итога
или снятия отметки — это входит в согласие на кнопку). Шаг идёт больше часа,
а журнал не растёт 20 минут — строка «журнал не растёт N мин — возможно,
зависло» (ничего не убивается). Прервалось — причина, журнал, «Попробовать
снова» (ещё две попытки) и «Убрать отметку — обновлять не буду»
(`goinstall --os-upgrade dismiss`): состояние уходит в
`os-upgrade/state.failed-<время>`, журнал остаётся. «Идёт», а исполнителя
нет — это «прервано», а не вечный запрет: служба упала (`failed`) или
включена, но не работает и не ждёт запуска — «исполнитель обновления упал —
журнал …»; службы нет (сняли вручную, `enable` не прошёл) — «служба
обновления не работает». Готово —
итог: что сделано и что проверить; открыли итог — пункт из меню уходит.

Пока обновление идёт, goInstaller не ставит и не обновляет продукты,
компоненты, себя, не открывает меню продуктов, не трогает размер пакета
сети (`--net`) и не удаляет себя: «идёт обновление Ubuntu — дождитесь
окончания».

Отказ установки только по ОС на Ubuntu 20.04/22.04, который обновление
лечит, говорит, где оно: «Обновить Ubuntu до 24.04 можно из меню goinstall —
пункт o (или goinstall --os-upgrade)».

### Для сопровождающих

Механизм проверен на серверах 14.10: `do-release-upgrade -f
DistUpgradeViewNonInteractive` из службы systemd без терминала проходит без
вопросов (код 0) и сам не перезагружает. Поэтому:

- `osup_start` пишет `/opt/go-installer/os-upgrade/` (0700): `state`
  (key=value: `status=running|failed|done`, `from`, `target`, `started`,
  `finished`, `reboots`, `attempt`, `step`, `msg`, `seen`; время шагов
  `t:<шаг>=начало конец`, попытки прыжка `n:rel-<выпуск>`; `did=` и `note=`
  итога), `log`, `before/` (стоящие пакеты, `apt-mark showmanual`,
  работавшие службы, контейнеры, был ли ufw, списки источников, кодовое имя,
  `Prompt`, порты SSH, что помечено вручную), `runner.sh` — копию скрипта:
  самообновление пишет goinstall на месте, а bash читает скрипт по ходу;
- временный `/etc/apt/apt.conf.d/99goinstall-os-upgrade` с
  `--force-confdef --force-confold`; `Prompt=lts` в
  `/etc/update-manager/release-upgrades` на время обновления;
- `apt-mark manual` стоящим пакетам групп «Компонентов» (кроме пакетов
  конкретного python: python3.10 на 24.04 нет). Пометку не снимаем;
- службу `/etc/systemd/system/goinstall-os-upgrade.service` (oneshot,
  `TimeoutStartSec=0`, после `network-online.target`, вывод — в `log`),
  `enable` и `start --no-block`.

`runner.sh` — копия той же версии, что запущена: `$0` или `goinstall` с тем
же `GOINST_VERSION`; иначе отказ до всего: «сначала обновите команду
goinstall». Служба после каждой загрузки зовёт `runner.sh --os-upgrade-run`
(под `flock`, два исполнителя сразу не идут) — шаг за запуском, выпуск
перечитывается после каждого шага, меняющего пакеты: восстановление dpkg,
если обрыв (`dpkg --configure -a`, `apt-get -f install`); пакеты текущего
выпуска (`apt-get dist-upgrade`, при нужде перезагрузка); ожидание замка apt
(до 15 минут); `/var/run/reboot-required` — перезагрузка до прыжка (прыжок
не начат, попытка не сгорает); прыжок `do-release-upgrade` — единственный
вызов, в `osup_dru`, с последней сверкой выпуска перед ним. Выпуск вырос и
код 0 — перезагрузка; код ошибки при выросшем выпуске — восстановление и
`dist-upgrade`, чисто (`dpkg --audit` пуст) — дальше с замечанием в журнале,
нет — «прервано» без перезагрузки; выпуск не вырос — «прервано» без
перезагрузки. Прыжок оборвался после смены выпуска (base-files уже новый) —
восстановление, `dist-upgrade`, перезагрузка, если её просят, и только потом
отметка. Перезагрузка в недонастроенный dpkg не идёт никогда. Отметка шага
— только после успеха. Оборванный прыжок повторяется один раз. Больше 8
запусков — «круг перезагрузок». На 24.04 `do-release-upgrade` не зовётся
никогда: завершение — SSH слушает прежние порты (иначе перезапуск
`ssh.socket`); списки продуктов `*.list.distUpgrade` → `.list` с noble,
если репозиторий его отдаёт (чужие не трогаем; выключается
`GOINST_OSUP_FIX_LISTS=0`); пропавшие пакеты групп ставятся снова
(`install --no-install-recommends --no-remove`, сторонние — нет); упавшие
службы перезапускаются; DKMS — заголовки ядра и `dkms autoinstall`;
контейнеры, ufw — сверка. Сбой здесь — замечание, а не «прервано»: ОС уже
обновлена. В конце и при сбое убираются apt.conf, `Prompt`, служба и копия
скрипта; `state`, `log` и `before/` остаются.

Снять вручную, если что-то пошло не так, — службу и отметку «идёт»:

```
systemctl disable --now goinstall-os-upgrade.service
rm -f /etc/systemd/system/goinstall-os-upgrade.service /etc/apt/apt.conf.d/99goinstall-os-upgrade
rm -f /etc/profile.d/goinstall-osupgrade.sh
systemctl daemon-reload
mv /opt/go-installer/os-upgrade/state /opt/go-installer/os-upgrade/state.failed-manual
```

Без последней строки goInstaller и сам покажет «прервано: служба обновления
не работает» — оттуда «Убрать отметку» или `goinstall --os-upgrade dismiss`.
`Prompt` в `/etc/update-manager/release-upgrades` верните сами (прежнее —
`/opt/go-installer/os-upgrade/before/prompt`), если снимали без goInstaller.

Журнал — `/opt/go-installer/os-upgrade/log`, журнал апгрейдера —
`/var/log/dist-upgrade/main.log`.

## Защита от сканеров

С 1.2.0 goInstaller предлагает защиту сразу после выбора языка, до ключа и
продуктов (только в терминале и один раз: отказ запоминается, включить потом
можно в меню). Ответ — «1) Да / 2) Нет». Набранное до вопроса (например,
Enter на отсчёте сводки) сбрасывается: ответом считается только нажатое после.

Что делает:

- **Защита (входящие; пункт 1 «Выключить защиту» / «Включить защиту»).**
  Соединения из сетей госорганов и ВК, из которых сканируют серверы,
  отбрасываются — и новые, и уже установленные: сканер не видит ваших портов.
  SSH и ответы на соединения, которые открыл сам сервер (или клиент VPN через
  него), не трогаются.
  Включается по «Да».
- **«ВК: не выпускать» (исходящие; пункт 2).** Соединения к сетям ВК
  отклоняются сразу (tcp reset), приложения не висят: Макс и ВК через VPN не
  засветят адрес сервера. С 1.2.2 по умолчанию включено — по «Да», `--shield on` или пункту
  меню там, где защиты ещё не было, вместе со сканерами (если список ВК принят
  и не пуст; пустой или не прошедший проверку не включается, об этом сказано).
  Сам сервер тоже перестаёт ходить в сети ВК (бот, Xray goVLESS pro, apt).
  При включении (и в меню — до вопроса) списком сказано, что не будет работать
  через VPN и с самого сервера: ВКонтакте и VK Видео, Одноклассники, Mail.ru
  (почта, облако), мессенджер Макс, Дзен, RuStore, Юла, VK Play, VK Cloud и
  другие сервисы VK (состав сверен с сетями списка ВК). Выключить — пункт 2 в
  меню «Защита от сканеров» или `goinstall --shield vk off`. Где защита уже
  стояла, выбор не меняется: ВК, выключенный раньше (в том числе прежним
  умолчанием), остаётся выключенным.
  - **goVLESS pro или бесплатный Lite в режиме Reality** маскируется под чужой
    сайт и ходит к нему на каждое соединение клиента. Если этот сайт в сетях
    ВК (в списке goVLESS pro для серверов в РФ есть vk.com, ok.ru, dzen.ru),
    закрытый ВК остановил бы VLESS у всех: тогда ВК по умолчанию не
    включается, а `vk on` отказывает — с объяснением. Сайт сверяется по его
    адресам со списком ВК (ваши исключения учитываются), без сети — по имени.
    Сайт не прочитан из `/opt/govless/config.json` — ВК по умолчанию тоже не
    включается и это сказано; `vk on` тогда включает с предупреждением.
    Защита предлагается до продуктов: если goVLESS pro поставили позже при
    включённом ВК, после его установщика будет предупреждение со списком, где
    первая строка — «VLESS Reality этого сервера (маскировка под …) — у всех
    клиентов» (выбор ВК не меняется — выключить в меню или `vk off`).
  - **Узел РФ goKaskad pro** — без исключения (решение владельца 03.11): ВК,
    ОК, Mail.ru и Макс у клиентов каскада тоже не откроются. Об этом одна
    строка после списка при включении ВК и после установщика goKaskad pro;
    выключить — в меню.

Списки — открытый проект [AS_Network_List](https://github.com/C24Be/AS_Network_List)
(BSD-2), обновляется каждый день. Ключ клуба туда не отправляется. Каждый
список проверяется до применения: только строгие записи сетей, без слишком
широких, не меньше 300 сетей, не меньше половины прошлого и не больше чем втрое.
Охват считается в адресах: общий список v4 не шире 16 384 сетей /24 (одна /10,
около 10× нынешнего), v6 — 16 777 216 сетей /48, и не больше чем втрое против
прошлого (маленький прошлый список рост не запирает: втрое считается не меньше
чем от 1 024 сетей /24 и 1 048 576 /48). Список ВК v4 должен лежать внутри
общего, и ни одна сеть ВК не должна задевать адреса GitHub, откуда goInstaller
качает (иначе подменённый список отрезал бы сервер от обновлений). Не прошёл —
работает прошлый принятый список, а причина видна в статусе. Список ВК
проверяется отдельно: если не прошёл только он, общий список обновляется, а
для ВК остаётся прежний — об этом сказано в статусе и в меню (пока ВК
выключен — серым, с пометкой «ВК выключен»). Если прежнего нет (первая
установка), ВК пуст: так и сказано при установке, в статусе и в меню, «ВК
для клиентов VPN» остаётся выключенным и не включится, пока не придёт
исправный список (тогда — в меню). Новая установка, у которой список ВК не
прошёл проверку, ВК не включает и тогда, когда прежний есть (остался от
неудачной установки): он не сверен с причиной отказа.

Адреса GitHub сверяются со списком ВК и при включении ВК, и раз в час, пока
ВК включён: GitHub сменил адрес, и он оказался в сети ВК, — ВК не включится,
а включённый даст `✗` «ВК закрыл GitHub» (код 1 у `--shield check`) с
сетью, адресом и советом: выключить ВК или добавить адрес в исключения.
Добавили — сбой снимается сразу. Если адреса GitHub не разрешились, сверка
не молчит: в журнале «сверка пропущена» или «неполная».

Никогда не блокируются: SSH (порты sshd, его настроек и `ssh.socket`
сверяются при каждой проверке; сменили порт или перезапустили sshd — правила
пересобираются сразу, слежка `goinstall-shield.path`), адреса самого сервера, частные и служебные сети, сети МТС
(`TVK-AS`: иначе домашние клиенты МТС не подключились бы к VPN) и ваши
исключения. Свои добавки — отдельным списком.

Правила — одна своя таблица nft `inet goinstall_shield`. Чужие правила,
таблицы продуктов, ufw, iptables, Docker, `/etc/nftables.conf` и служба
`nftables` не трогаются. Нет nft — по «Да» ставится ровно пакет `nftables`; в
контейнере (OpenVZ, LXC) защиту не поставить, об этом сказано словами.

Раз в час таймер `goinstall-shield.timer` проверяет, что таблица на месте
(нет — применяет заново, в журнале «восстановлено»), и раз в сутки обновляет
списки. После загрузки правила применяет `goinstall-shield.service` — из
сохранённого, без сети (загрузку не задерживает, сети не ждёт); первые 10 минут
после загрузки защита в сеть не ходит, списки обновит таймер (в журнале
«обновление отложено: N с после загрузки»). После
установщика продукта — та же проверка. Если защита занята (например, таймер
качает списки при недоступном GitHub), команда или меню сразу говорят, что
ждут, и ждут до 3 минут. Не работает или список старше трёх суток — `✗` в меню, в
сводке при входе и код 1 у `--shield check`, с причиной (не скачался —
почему, или отклонён — почему).

Таймер запускает свою копию скрипта `/opt/go-installer/shield/runner.sh`, а не
`goinstall`: смена версии goinstall (самообновление, запуск другой ветки) защиту
не ломает. Если новая версия goInstaller защиты не знает, правила продолжают
работать, а goInstaller пишет, как их снять: `bash
/opt/go-installer/shield/runner.sh --shield remove --yes`. Снимайте до удаления
goInstaller: старая версия при удалении защиту не снимет.

В меню — пункт «s Защита от сканеров» (`вкл · N сетей · список от ДД.ММ`,
`выкл` или `✗ не работает`): сканеры вкл/выкл, ВК вкл/выкл, обновить списки,
исключения, свои добавки, удалить защиту.

```bash
goinstall --shield            # состояние (код 0 работает, 1 не работает, 3 не стоит)
goinstall --shield check      # проверить и восстановить
goinstall --shield update     # скачать списки сейчас
goinstall --shield on         # включить (поставить; новая установка — сканеры и ВК)
goinstall --shield vk off     # пропускать соединения к сетям ВК (vk on — снова отклонять)
goinstall --shield off --yes  # выключить сканеры, ВК — как был (без терминала — только с --yes, иначе код 64)
goinstall --shield remove --yes   # снять защиту целиком (статистика остаётся)
```

### Статистика защиты (с 1.2.4)

Защита считает, сколько раз сети сканеров пытались подключиться (вход) и
сколько соединений к сетям ВК она не выпустила (выход: отдельно от клиентов
VPN и от самого сервера). Прокси на самом сервере (3X-UI и xray, telemt,
mtg) считаются клиентами; если nft или ядро этого не умеют (Ubuntu 20.04), их
соединения попадут в колонку «сервер», и отчёт подпишет: «сервер и прокси на нём» (прокси нет — «сам сервер»). Сканеры выключены —
сервер не блокирует, но считает. ВК выключен — выход не считается. Считается только новое
подключение (повтор SYN — ещё одна попытка), SSH не считается: он открыт
всегда.

В сводке при входе по SSH — «пока вас не было» (с прошлого показа сводки):
попытки, адреса, соединения к ВК, всплеск за сутки, три самые активные сети
(предположительно, по названию сети в списке). Защита выключена — сводка
говорит, что сервер только считает, и как включить.

```bash
goinstall --shield stats          # всё: «пока вас не было», сутки, 7 и 30 дней, всё время, часы, дни, порты, топ
goinstall --shield stats 24h      # одно окно: 24h, 7d, 30d или all
goinstall --shield stats top 7d   # топ-30 сетей сканеров за период
goinstall --shield stats size     # сколько весит, с какой даты, сколько адресов
goinstall --shield stats reset --yes   # обнулить (без терминала — только с --yes)
```

Вывод — текст для скриптов: ключ раздела в первой колонке, числа вправо.
Коды: 0 — показано, 1 — не прочесть, 3 — защиты и статистики нет, 64 —
неверная команда или `reset` без терминала без `--yes`.

Раз в час таймер защиты делает снимок счётчиков (сеть для этого не нужна) в
`/opt/go-installer/shield/stats/` (только root): часы за 40 дней, дни — без
срока, до 200 тыс. адресов. Обновление goInstaller, пересборка правил,
перезагрузка и `--shield remove` статистику не стирают (после перезагрузки
теряется не больше часа счёта). После `--shield remove` команда
`goinstall --shield stats reset` удаляет её совсем; удаление goInstaller
удаляет её вместе со всем. Если nft или ядро не умеют часть счёта (старое
ядро), защита работает как прежде, а в статистике — «нет данных» по тому,
чего не посчитать.

Файлы — `/opt/go-installer/shield/` (только root): принятые списки, настройки,
исключения, добавки, `shield.nft`, журнал `shield.log`, копия скрипта
`runner.sh`. Снять вручную, если goInstaller уже нет:

```bash
nft delete table inet goinstall_shield
systemctl disable --now goinstall-shield.timer goinstall-shield.path goinstall-shield.service
rm -f /etc/systemd/system/goinstall-shield.{service,timer,path}
systemctl daemon-reload
rm -rf /opt/go-installer/shield      # вместе со статистикой
```

После `--uninstall` версии без защиты юниты остаются, но не запускаются (нет
копии скрипта: таймер и слежка после загрузки не стартуют), а таблица живёт до
перезагрузки — снимите её первой командой.

## Удаление goInstaller

Пункт «x Удалить goInstaller» в главном меню или команда:

```bash
goinstall --uninstall
```

Уходит только сам goInstaller: команды `goinstall` и `go-installer`, каталог
`/opt/go-installer` (кеш версий, язык, размер меню), таймер сводки при входе и
скрипт входа, защита от сканеров (её таблица nft, таймер, списки и статистика —
об этом сказано в подтверждении). Продукты, их команды и настройки остаются и работают. Размер
пакета сетевой карты, если его меняли через `goinstall --net`, тоже остаётся:
без него вернутся обрывы связи с GitHub.

Ключ клуба — по выбору: удалить вместе со всем или оставить. Оставленный
ключ подхватит goInstaller при новой установке, а goKaskad pro берёт его как
запасной, когда скачивает ядро AmneziaWG.

Без терминала команда ничего не спрашивает и не удаляет (код 3); для скриптов —
`goinstall --uninstall --yes`, ключ при этом уходит, оставить —
`--keep-key`. Поставить goInstaller снова можно той же командой из клуба.

## Размер меню и F-клавиши

На большом окне меню растягивается во всю ширину (до 160 колонок) и встаёт
по центру. F2 переключает размер по кругу: на всё окно → 80×24 по центру →
80×24 в углу, как раньше. Выбор запоминается. Сами буквы крупнее делает
терминал: в Termius и iTerm — Cmd+.

F-клавиши дублируют буквы: F2 — размер, F3 — карта портов, F4 — язык. На
Mac их жмут с Fn, в Termius на телефоне они есть в панели клавиш.

## Плохая связь с GitHub

С 1.0.7 goInstaller рассчитан на медленную и рвущуюся сеть до GitHub:

- каждый запрос повторяется до 4 раз с паузами 2, 4 и 8 секунд — но только
  при сетевом сбое; окончательный ответ GitHub («нет доступа», «нет ветки»,
  лимит) не повторяется;
- на соединение отводится до 30 секунд, на попытку — до 60;
- если сервер долго узнаёт адрес GitHub, адрес узнаётся один раз за запуск;
- когда GitHub молчит совсем, goInstaller не ждёт по кругу: исчерпав попытки
  на одном запросе, остальные запросы того же захода он не повторяет.

Что происходит, видно на экране: при скачивании — каждая неудачная попытка и
её причина, при проверке ключа — «Попытка 2 из 4: причина. Жду ответа
GitHub», на заставке меню — строка о повторах, а если ответа так и не было —
причина словами и сколько раз пробовали. Причины: не работает DNS, путь до
GitHub закрыт, время ожидания вышло, соединение рвётся на полпути, сертификат
не прошёл проверку (неверное время на сервере или нет `ca-certificates`).

Настроить: `GOINST_GH_TRIES`, `GOINST_GH_CONNECT_TIMEOUT`,
`GOINST_GH_TIMEOUT`, `GOINST_GH_RETRY_DELAY`.

## Размер пакета до GitHub

Бывает, что хостер отдаёт виртуальной машине сетевую карту на 1500 байт, а
его сеть пропускает меньше. Тогда соединения с GitHub могут рваться:
`curl: (28) SSL connection timeout` то при опросе версий, то при скачивании
установщика. Ключ тут ни при чём.

goInstaller проверяет это сам при открытии меню и перед `--install`, а
вручную — командой `goinstall --net`. Если путь до GitHub уже, чем настроена
карта, он объясняет это и предлагает исправить цифрой. По ответу «1»:

1. ставит карте размер, который пропускает путь;
2. проверяет делом, что полный пакет теперь проходит до того же адреса
   GitHub (две попытки), а если нет — возвращает прежний размер и ничего не
   записывает;
3. записывает размер туда, где сеть настраивается после перезагрузки:
   `/etc/network/interfaces` или netplan, с копией прежнего файла рядом.

Адресов у GitHub несколько, и не каждый отвечает на большие пакеты:
20.250.119.72 для `api.github.com` отвечал только на 56 байт. Поэтому
проверка берёт первый из (не больше трёх) адресов, ответивший на ping в
1200 байт, — по одной пробе на адрес, так что запуск меню не ждёт дольше
прежнего. Не ответил ни один — при запуске молча дальше, а `--net` называет
причину.

Это единственное, что goInstaller меняет в системе, и только по согласию. Без
терминала он лишь сообщает и подсказывает команду. Отказ запоминается, пока
размер пути тот же; `goinstall --net` спросит снова.

Ошибка скачивания без ответа от GitHub теперь называется сетевой, а не
«проверьте ключ», и скачивание повторяется до трёх раз.

## Что проверяется

Три уровня у каждого порта, снятые с кода продукта, а не придуманные:

- **✗ препятствие** — без этого порта продукт не встанет или сломает
  соседа. Установка не запускается (`GOINST_FORCE=1` снимает запрет).
- **! замечание** — у продукта есть запасной вариант или порт нужен
  только для необязательной части. Установка идёт, установщик продукта
  спросит сам.
- **· к сведению** — порт просто станет занят или будет взят, если свободен.

Порт, который держит **тот же продукт**, при переустановке или обновлении
занятым не считается.

Юнит `x-ui` бывает у любой панели 3X-UI, а не только у goVLESS pro: её ставили
и по старым инструкциям, и вручную. Порты такой панели приписываются goVLESS
pro, только когда он сам стоит, иначе их владелец — «3X-UI». Для установки
goVLESS pro чужая панель не препятствие: его установщик оставляет её и берёт
себе, и проверка предупреждает об этом замечанием. Соседям она мешает как
3X-UI, а не как goVLESS pro. Владелец определяется по systemd-юниту процесса
(`/proc/<pid>/cgroup`): `x-ui`, `govless-*` → goVLESS pro; `telemt`,
`gotelegram-*` → goTelegram pro; `dnsdist`, `godns-*` → goDNS pro; `kaskad-*` →
goKaskad pro; `warp-svc`, `warp-bot` → goWARP pro. Для nginx владелец — тот, чей
сайт включён в `sites-enabled`.

Требования к системе сняты с установщиков продуктов, и проверяются так же,
как проверяет сам продукт:

- goVLESS pro при **новой** установке требует Ubuntu 24.04+ или Debian 12+;
  обновление стоящего (и pro поверх бесплатного Lite) не блокируется;
- goTelegram pro при **первой** установке требует Ubuntu 24.04+, на Debian —
  замечание; стоящий обновляется на любой системе;
- goDNS pro — только Ubuntu 22.04+, проверяет при каждом запуске;
- goAmnezia pro — только amd64; на Ubuntu 20.04 замечание: бот (python 3.8)
  и сайт (certbot 0.40) не встанут, AmneziaWG встанет;
- goKaskad pro и goWARP pro по выпуску не отказывают (goKaskad pro 3 на
  Ubuntu до 24.04 работает на iptables и без шлюза).

## Как запускаются установщики

| Продукт | Откуда | Что запускается | Ключ |
|---|---|---|---|
| goVLESS pro | `duboshin52/goVLESS@main` | `bootstrap.sh` → клон в `/opt/govless-installer`, чужой клон вроде Lite заменяется → `govless.sh` | `GH_TOKEN` |
| goTelegram pro | `duboshin52/gotelegram_pro@main` | `bootstrap.sh` → файлы по SHA ветки в `/opt/gotelegram` → `install.sh` | `GOTELEGRAM_PAT` |
| goDNS pro | `duboshin52/goDNS@main` | `install.sh` → tarball через api.github.com → `/opt/godns-installer` | не нужен; `GH_TOKEN` необязателен |
| goKaskad pro | `duboshin52/kaskad-pro@main` | `install.sh` — сам себе программа, копирует `$0` в `/usr/local/bin/gokaskad` | заголовок при скачивании |
| goWARP pro | `duboshin52/go_warp_pro@main` | `warp.sh <лицензионный ключ>` — то же, копирует себя в `/usr/local/bin/gowarp` | заголовок при скачивании |
| goAmnezia pro | `duboshin52/goamnezia_pro@main` | `bootstrap.sh` → срез ветки по SHA в `/opt/goamnezia` → `install.sh`; Ленивый pro — `bootstrap.sh --lazy` | `GOAMNEZIA_PAT` |

Ключ передаётся только через окружение и конфиг-файл curl с режимом 0600 —
в аргументы команд он не попадает (`/proc/<pid>/cmdline` читает любой
локальный пользователь). goKaskad pro и goWARP pro запускаются **из файла** в
`/opt/go-installer/<id>/`, а не из подстановки процесса: иначе их
самокопирование в `/usr/local/bin` не срабатывает.

Безголовый путь в серии один — Ленивый pro у goAmnezia pro: `--lazy` без
меню продукта, из вопросов остаются домен (или `GOINST_LAZY_DOMAIN`) и бот в
конце. Остальные мастера задают вопросы сами, и goInstaller после проверки
просто отдаёт терминал.

## Тесты

```bash
./test_goinstaller.sh
```

Нужен bash 4.0+ — на macOS штатный 3.2 пропускает набор целиком, там
вызывать `/opt/homebrew/bin/bash`. Порты, юниты и ОС берутся из фикстур,
GitHub — поддельный `curl`, `systemctl` — заглушка; система не трогается.

Меню «Аркада» проверяется тремя способами:

- **клетка в клетку с макетом.** 25 экранов в двух ширинах и на двух языках
  (92 сверки) рисуются тем же кодом и сверяются с экранами пакета Claude
  Design (`design/handoff/spec/screens`): символ и роль цвета каждой клетки;
- **настоящим циклом.** `ui_main` получает клавиши через FIFO по одной и
  пишет журнал «клавиша → экран» (`GOINST_UI_TRACE`); всё, что меняет
  систему, заглушено и отчитывается, что именно вызвали;
- **по кусочкам.** Чтение клавиш (стрелки обоих режимов, раскладка,
  вставка), ширина окна, локаль, компоненты на заглушках `dpkg-query`,
  `apt-cache`, `apt-mark` и `apt-get` в PATH, сертификаты на выпущенных `openssl`
  сертификатах, сводка при входе, сводка версий и её публикация в локальный
  git-репозиторий.

Ручная проверка на живой машине без установки:

```bash
GOINST_NO_SELF_INSTALL=1 bash go-installer.sh --ports
GOINST_NO_SELF_INSTALL=1 bash go-installer.sh --check gotelegram pro
```
