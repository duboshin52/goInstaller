№9 (заметно, К3-5) — блок не рвал уже подключённого.
  Код: цепочка incoming (python, :5460–5468): lo; порты SSH; @allow4/@allow6;
    ip saddr @scan4 ct direction original counter drop (и v6); ct state established,related accept;
    ip saddr @scan4 counter drop (и v6). Эталон shield.nft в наборе обновлён.
  Тест: эталон и порядок (sed 2,12p) и модель цепочки $SF/nfteval.py (:5597, проверка :5653):
    от адреса из списка — new drop, est (исходящее от клиента, уже установленное) drop, reply
    accept, icmperr (RELATED_REPLY) accept, ssh accept, invalid drop, lo accept; v6 так же; чужой
    адрес — accept.
  Мутации: m9a (established первым) — 3 FAIL; m9b (drop без ct direction — режет ответы) — 3;
    m9c (без хвостового drop) — 5; m9d (без ревизии правил в отпечатке) — 3.
  Почему ответы на исходящие сервера не режутся. Prerouting priority -150 идёт после conntrack
    (-200), поэтому у пакета уже есть направление. Ответ на соединение, которое открыл сам сервер
    (или клиент VPN через NAT/forward), имеет ct direction reply и под `ct direction original`
    не попадает; дальше его принимает established. ICMP-ошибки к таким соединениям — related в
    направлении reply, тоже проходят. Пакет reply всегда established или related, поэтому хвостовой
    drop ловит только пакеты без записи conntrack (invalid/untracked: FIN/NULL/XMAS-сканы) — как
    раньше, до перестановки, это делал единственный drop. SSH и allow стоят выше — SSH не режется
    никогда. Последствие (так и задумано): соединение, открытое С адреса из списка (в т.ч. уже
    установленное, и data-соединение пассивного FTP оттуда), рвётся на первом же пакете.
    Цена — две лишние проверки набора на пакет от адресов вне списка до established.

Как проверить вживую (тестеру)
  1. bash <(curl … test-shield-r3 …) на сервере с прежней test-shield 1.2.0: goinstall → 1.2.1,
     /opt/go-installer/shield/runner.sh — новый (cmp с goinstall).
  2. nft list table inet goinstall_shield: порядок как в №9; nft -c -f …/shield.nft — без ошибок.
  3. Подключиться к серверу (не SSH, например к порту VPN) с адреса, затем внести его в список
     (shield add/тестовый список) — соединение рвётся на первом пакете; исходящий curl с сервера
     на адрес из списка работает.
  4. docker restart <контейнер> / перезагрузка — в shield.log нет «пересобраны» (кроме первого
     такта после обновления).
  5. for l in C.UTF-8 en_US.UTF-8 C.UTF-8; do LC_ALL=$l goinstall --shield status; done — ни одной
     пересборки.
  6. Без сети (drop на 443 к GitHub) bash go-installer.sh без goinstall: строка «Ищу ветку…»,
     попытки 1–3 из 4, один круг (~134 с), «не установлена: … (сеть)».
