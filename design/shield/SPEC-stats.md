# Статистика «Защиты от сканеров» — goInstaller 1.2.4 (ветка `test-shield`)

Решения владельца 03.11.2026. Макет — `design/shield/handoff-stats/goinstaller-shield-stats/project/`
(README-shield.md, shield-screens.js, menu-screens.js, spec/screens/arcade_{shield,menu}_{ru,en}.json,
spec/tokens-shield.json, spec/ascii-fallback-shield.json). Бриф — `stats-design-brief.md`. Основа — SPEC.md защиты.

## Решения владельца

- Два счётчика: **Вход = сканеры** («Вход · сканеры остановлены: N попыток · M адресов») и **Выход = утечка
  вашего IP** («Выход · утечка IP предотвращена: K соединений к сетям ВК»). ВК выкл — «Выход · выкл · защита от
  утечки IP не работает» (warn). Сканеры выкл — сервер не блокирует, но СЧИТАЕТ, и рекомендует включить.
- Статистика — в уведомлении при входе по SSH (сводка `--motd`, sh-a/b/c); график — в главном меню
  (карточка у пункта `s` и строка-спарклайн **вариант A — под списком**, всегда видна).
- График — «бабочка»: ось времени строго ровная по центру, вход влево, выход вправо, у сторон свой масштаб.
  Четыре вида: 24 ч, 7 дней, месяц, всё время.
- Топ-30 сканеров по названию сети (предположительно, по подписи в списке), с выбором периода.
- Настройки статистики: сколько весит, с какой даты, сколько адресов; «Обнулить» (1 Да / 2 Нет, Enter — Нет).
- Статистика хранится отдельно и **не слетает** при обновлении goInstaller, пересборке правил, перезагрузке.
- Дополнительно (предложено и принято с макетом): порты под сканированием с пометкой, чей порт; новые и
  повторные адреса; час пика; всплеск (≥ 2× медианы периода и не меньше разумного абсолютного порога).
- Подвал с благодарностью C24Be — текст из брифа, дословно.

## Шаг 1 — сбор и хранение (высокий риск: правила сети, чужой ввод)

1. **Правила.** В той же таблице `inet goinstall_shield`, одной транзакцией, как сейчас:
   - попытки входа: счётчик новых подключений из `@scan4/@scan6` (`ct state new`), отдельно от счётчиков drop;
   - разные адреса: динамические наборы `flags dynamic,timeout` (v4 — адрес, v6 — /64), `update @… { … }`;
     срок записи ≥ 35 дней; размер ограничен (`size`), переполнение не ломает правило;
   - порты и попытки по адресу — если nft и ядро умеют (счётчик в динамическом наборе / конкатенация с портом):
     проверить `nft -c` при сборке; не умеют — правило не ставится, в статистике «нет данных», остальное работает.
     Проверить на Ubuntu 20.04 (nft 0.9.3), 22.04, 24.04 (стенды Lima);
   - выход: счётчики новых соединений к `@vk4/@vk6` раздельно `forward` (клиенты VPN) и `output` (сам сервер);
     уточнение 03.11 (REVIEW-6 №6): выход служб-прокси на сервере (x-ui/xray, telemt, mtg) — тоже «клиенты VPN»
     (`socket cgroupv2`); nft или ядро не умеют — подпись «сервер и прокси на нём», без ошибок (К5-17, 1.2.5: только если служба прокси работает; нет — «сервер — сам сервер»);
   - **сканеры выкл** (`scan 0`): таблица остаётся с правилами счёта БЕЗ drop (сейчас при выкл правил нет —
     сверь); `remove` снимает всё. ВК выкл — правил выхода нет, выход «не считается».
   - SSH, allow, порядок правил и К3-5 (`ct direction original drop`) не меняются; эталон shield.nft обновить.
2. **Снимок раз в час** (тот же такт таймера `--shield tick`, без сети): прочитать счётчики (`nft -j`), наборы
   адресов; дельты к прошлому снимку (счётчик меньше прошлого — пересборка/перезагрузка: дельта = новое
   значение); записать в `/opt/go-installer/shield/stats/` (каталог 0700, файлы 0600, запись атомарно через
   временный файл + mv):
   - часовые корзины (вход, адресов за час, выход клиентов, выход сервера, порты) — 35+ дней;
   - дневные итоги — без срока (малые);
   - база адресов: адрес(/64), первый и последний раз, попытки если есть, сеть/AS — с пределом размера
     (например 200 тыс. строк; старые по last_seen вытесняются; «всего адресов» — отдельный счётчик);
   - владелец сети: адрес → сеть принятого списка → подпись AS из `blacklist_with_comments.txt` (уже
     скачивается для TVK-AS); нет подписи — «без подписи в списке». Подпись — чужой ввод: печатаемые символы,
     длина ≤ 60, без управляющих последовательностей.
   - сводка для входа (`summary`) — готовые числа, чтобы `--motd` ничего не считал.
3. **«Пока вас не было»**: время прошлого показа уведомления хранится в stats/ (0600); при показе — сумма
   корзин с той отметки, затем отметка обновляется. Только интерактивный вход root (как сейчас у сводки).
4. **Не слетает**: `self_install`/обновление, `shield_apply`, перезагрузка, `shield update` stats/ не трогают;
   тест. `--shield remove` — статистику НЕ удаляет (сказать, где лежит и как удалить: `--shield stats reset`);
   удаление goInstaller — удаляет всё (сказать в подтверждении, как сейчас).
5. **Команды**: `goinstall --shield stats [24h|7d|30d|all]` (без tty — sh-f, ключи разделов в первой колонке),
   `--shield stats top [период]` (топ-30), `--shield stats size`, `--shield stats reset` (без tty — только с
   `--yes`). Коды как у остальных `--shield`.
6. **Нагрузка**: такт ≤ ~1 с CPU на сервере с 200 тыс. адресов; память наборов в ядре — оценить и записать.
   ~1400 серверов клуба — никакой сети ради статистики.

## Шаг 2 — экраны (по макету клетка в клетку)

- Сводка при входе sh-a/sh-b/sh-c (80 и 46, ru/en) — строки как в `arcade_shield_*.json`.
- Главное меню: карточка «Защита» при курсоре на `s` (g2), две строки счётчиков (g1), спарклайн вариант A;
  `shield_rows` в `arcade_menu_*.json` — какие строки эталона меняются; эталоны `design/handoff/spec/screens`
  обновить ровно в этих строках.
- Меню «Защита» sh-d, статистика sh-e (виды 1–4, ↑↓ строка, точные числа), топ-30 sh-g (период 1–4, ↑↓,
  PgUp/PgDn, Home/End), настройки sh-h (сброс), вывод без tty sh-f.
- Новые токены `in`/`out` (`tokens-shield.json`), ASCII-замены `▁▂▃▅▇ ┊` (`ascii-fallback-shield.json`) —
  во все четыре режима цвета и в ASCII-рамки. Дамп по клеткам сверяется с JSON макета, как прежние 24 экрана.
- Клавиши — цифры и стрелки на каждом экране, русская раскладка, Enter-глотание — как в «Аркаде».
