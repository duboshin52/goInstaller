№1. СЕРЬЁЗНО — ВК по умолчанию глушит goVLESS pro (режим Lite/Reality) на сервере в РФ с маскировкой vk.com / ok.ru
  Где: go-installer.sh:6441 (умолчание vk=1) + цепочка vk_output (reject к @vk4/@vk6 без исключений, кроме @allow).
  Доказательство (по коду, вживую не гонял):
   - goVLESS сам предлагает эти домены для РФ-серверов: govless/.../lib/reality_domains.sh:62 "ok.ru", :85 "vk.com"
     (то же в goVLESS lite/lib/reality_domains.sh:57,80); выбор хранится в /opt/govless/config.json → mask_domain;
   - REALITY набирает dest на КАЖДОЕ входящее соединение до проверки клиента и закрывает его, если не вышло
     (XTLS/REALITY tls.go, Server(): config.DialContext(ctx, config.Type, config.Dest) → «REALITY: failed to dial dest»);
   - с ВК сам сервер не доходит до vk.com и ok.ru: stand-log.txt К3-6 (curl (7) за 0,02–0,05 с).
   Итог: человек отвечает «Да» на вопрос «Включить защиту от сканеров?», и VLESS этого сервера перестаёт работать у
   всех клиентов. До 1.2.2 так было только по явному «vk on» с вопросом (умолчание «Нет») и предупреждением.
  Как чинить: в shield_install, в ветке умолчания (settings нет), и в «vk on» (_shield_vk_gh_refuse — рядом):
   если стоит goVLESS (/opt/govless/config.json) и его mask_domain (чужой ввод: строго ^[A-Za-z0-9.-]+\.[A-Za-z]{2,}$,
   jq или python3 -I, не source) разрешается (getent, с таймаутом, как _shield_gh_addrs) в сеть списка ВК
   (_shield_py hits, как для GitHub) — ВК по умолчанию не включать (vk=0) и сказать словами: «goVLESS pro
   маскируется под <домен> — это сеть ВК, ВК закрыл бы VLESS. „ВК для клиентов VPN“ оставляю выключенным».
   «vk on» в том же случае — отказ словами. Если владелец предпочтёт принять риск — записать это в SPEC/README.
  Как проверить: тест в наборе — фикстура $GOINST_FS_ROOT/opt/govless/config.json {"mask_domain":"vk.com"} и
   подмена резолва в тестовом режиме (как GOINST_SHIELD_GH_ADDRS) адресом 45.1.3.7 → shield_install: settings vk=0,
   нет «chain vk_» в shield.nft, фраза про маскировку; без файла или с mask_domain вне ВК → vk=1. Без правки тест
   падает (сейчас vk=1).
  Рядом (вопрос владельцу, не подтверждено вживую): узел РФ goKaskad pro с «Российские сайты напрямую» — с ВК по
   умолчанию ВК и Макс клиентов каскада, идущие напрямую, отклоняются (vk_forward). Если так и задумано — одной
   строкой в README.

№2. ЗАМЕТНО — новая установка включает ВК по прежнему списку без сверки с GitHub
  Где: go-installer.sh:6441-6447 (vk=1 при SHIELD_VKERR≠""), shield_accept :5821-5827 (прежний ВК копируется).
  Когда: после неудачной установки списки остаются без settings (apt nftables не встал — rc 1 «предложу в
   следующий раз»; nft не работает/apply упал — rc 2). Следующая установка: новый список ВК отклонён (в т.ч. «сеть ВК
   с адресом GitHub») → берётся прежний → vk=1 без сверки с текущими адресами GitHub. «vk on» тот же список
   отказывает (_shield_vk_gh_refuse). Нарушает требование «сервер не теряет доступ к GitHub при vk=1» и README:789-790
   («ВК не включится»), и правило владельца «vk=1, если список ВК принят» (здесь не принят).
  Воспроизведение (стенд из фикстур набора):
   1) sh_reset; PATH=<фейк apt-get exit 1>:$PATH sh_run '_shield_have_nft(){ return 1; }; shield_apt_nft(){ return 1; };
      osup_lock_holder(){ :; }; shield_install'  → rc=1, lists/ остались, settings нет;
   2) GOINST_SHIELD_GH_ADDRS=45.1.3.9 sh_run 'shield_install' → «Список ВК не прошёл проверку: в списке ВК сеть
      45.1.3.0/24 с адресом GitHub 45.1.3.9 … Работает прежний ВК.» + «Сети ВК закрыты…», settings vk=1, vk_output
      в shield.nft; для сравнения shield_toggle vk 1 на том же → «ВК не включаю: … адресом GitHub», rc 1.
  Как чинить (минимально): в ветке умолчания (settings не было) при непустом SHIELD_VKERR — vk=0 и словами
   («новый список ВК не прошёл проверку — ВК оставляю выключенным; включить — в меню»); либо перед записью settings
   прогнать ту же сверку, что _shield_vk_gh_refuse, и при rc≠0 — vk=0. Ветку «settings уже был» не трогать.
  Как проверить: тест по шагам воспроизведения: после 2) — vk=0, нет «chain vk_», нет «Сети ВК закрыты».
   Плюс отдельный тест на чистой установке: GOINST_SHIELD_GH_ADDRS="45.1.3.7" sh_run shield_install → vk=0,
   «ВК пуст … оставляю выключенным» (сейчас поведение верное, но тестом установки не закреплено — есть только
   update/vk on/tick, test_goinstaller.sh:5995-6043).
