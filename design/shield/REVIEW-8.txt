№1. ЗАМЕТНО — _self_ref_caught сравнивает main со СТОЯЩЕЙ версией, а не с веткой: тестовый сервер теряет
     более новую сборку своей ветки (зависит от порядка выкладки)
  Где: go-installer.sh:2548 `ver_newer "$mv" "$iv" && return 0` (iv — версия goinstall).
  Комментарий над функцией говорит «main догнал ветку», код проверяет «main догнал стоящую».
  Воспроизведение (без сети, кеш руками): goinstall 1.2.5, .self-ref=test-shield, кеш @self.main=1.2.5,
  @self.test-shield=1.2.6 →
    до:    refs=[main test-shield] best=[test-shield 1.2.6]
    после _self_ref_caught: refs=[main] best=[main 1.2.5] selfref=gone
  То есть сервер на 1.2.5, у которого в своей ветке уже лежит 1.2.6, в момент, когда main принял 1.2.5, уходит
  с ветки и 1.2.6 не видит (нумерованное «u» и `--self-update` без ветки). Сервер, успевший встать на 1.2.6, —
  остаётся. Для конвейера «апрув → тест-ветка → main» это обычное состояние: main отстаёт на одну сборку.
  Как чинить: стирать, только если main не ниже и стоящей, и версии запомненной ветки:
    sv=$(ver_cache_get "$SELF_ID" "$saved") ; ver_newer "$mv" "$sv" && return 0   (sv пусто — как сейчас)
  Как проверить: в pathrun-блоке случай «main = эта версия, test-shield = 9.9.9 (S11), goinstall = эта» →
  запись остаётся, best=test-shield 9.9.9; без правки — gone и best=main. Прежние случаи (main догнал ветку,
  main новее) — без изменений.
