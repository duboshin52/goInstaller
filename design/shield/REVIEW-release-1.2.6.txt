1. ЗАМЕТНО (процесс; сейчас не срабатывает, сработает при первой же обычной правке test-shield)
   Свежая установка из main командой README (bash <(curl …main/go-installer.sh)) не ставит goinstall
   и молча не предлагает защиту, если в любой другой ветке лежит та же версия с другим файлом.
   - go-installer.sh:2918-2925 — self_ref_find: файлы одной версии из разных веток не совпали по cmp → «many».
   - go-installer.sh:3040-3047 — self_install: при «many» goinstall не ставится («Команда goinstall
     не установлена…» и подсказка скачать файл).
   - go-installer.sh:8219-8228 + :8901 — shield_runner_src не находит источник (GOINST_BIN нет, $0 — канал
     /dev/fd/NN) → shield_offer выходит молча, вопроса о защите нет.
   - Поведение задумано и закреплено тестом test_goinstaller.sh:7987-7989 (SELF_LIST=branches4.json:
     hit= many=a1 a2, shield=1).
   - Почему вероятно: CLAUDE.md:249 требует поднимать версию с каждой правкой, но в выпускаемом диапазоне
     44 из 52 коммитов, менявших go-installer.sh, версию не меняли
     (git rev-list origin/main..test-shield -- go-installer.sh + сравнение строки GOINST_VERSION=).
     До выпуска это было безвредно (main 1.0.12 ≠ 1.2.x). После выпуска main = 1.2.6, и первый же коммит
     в test-shield без смены версии ломает установку goinstall всем новичкам клуба.
     Попутно: коммит только в design/ (другой sha, тот же файл) даёт лишнюю загрузку ~1 МБ на каждую
     curl-установку (cmp совпадёт, вреда нет).
   Как воспроизвести: тест :7987 и есть воспроизведение. Живьём: ветки main и X, обе с 1.2.6, файлы
     разные → GH_TOKEN=… bash <(curl …/main/go-installer.sh) → предупреждение «в нескольких ветках»,
     /usr/local/bin/goinstall нет, вопроса о защите нет.
   Как чинить (до пуша код не трогать): правило «после выпуска первый коммит в любую ветку, меняющий
     go-installer.sh, поднимает GOINST_VERSION» (например 1.2.7-beta.1; refs/ver уже понимают -beta.N).
     Закрепить проверкой: шаг в CI или pre-push: для каждой ветки, если версия как у main, файл обязан
     совпадать с main. Менять «many» в коде — отдельный шаг: из канала ветку не узнать, выбирать молча нельзя.
   Как проверить: for b in $(git branch -r | grep -v HEAD); do v=$(git show $b:go-installer.sh 2>/dev/null |
     grep -m1 ^GOINST_VERSION=); [ "$v" = "$(git show origin/main:go-installer.sh | grep -m1 ^GOINST_VERSION=)" ] &&
     ! cmp -s <(git show $b:go-installer.sh) <(git show origin/main:go-installer.sh) && echo "КОНФЛИКТ $b"; done
     — пусто. Проверку стоит запускать перед каждым пушем в любую ветку.

   в 1.0.12 (old.sh:3486). Отказаться заранее можно только файлом /opt/go-installer/shield/declined.
   Как чинить: строка в README для скриптов владельцев (файл declined) или переменная GOINST_SHIELD=no.
   Как проверить: GOINST_SHIELD_TEST=1 GOINST_SHIELD_TTY=1 GOINST_SHIELD=no … --install <id> → вопроса нет,
     защита не стоит, код выхода как без неё.
